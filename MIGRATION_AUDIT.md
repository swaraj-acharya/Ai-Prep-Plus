## Findings and decisions

- **Task IDs:** 21 cloud-track tasks use `wNdMcloud` instead of `wNdMtK`; the ID schema accepts both
  (`/^w\d{1,2}d\d+(t\d+|cloud)$/`) so IDs remain stable and importable.
- **Book resources** (`ddia`, `alexxu`) have no URL in the source. Their source text is kept; a link is added at display
  time (`LINK_FIXES`: DDIA → dataintensive.net, 2nd edition 2026; Alex Xu → bytebytego.com).
- **Resources shown per week:** besides the resources each week names, week pages now list library resources whose own
  week range covers the week (13 resources such as Grafana, Loki, Helm, Argo CD and Playwright were never surfaced on a
  week page in the source).
- **Curated additions:** 68 resources added in `src/data/resources/curated.ts` (45 GitHub repos verified with git on
  2026-09-23), kept separate from the 142 source resources and marked "Added" everywhere. They fill gaps such as the
  missing prep resource for the AWS Solutions Architect – Associate certification, transformers-from-scratch code,
  advanced RAG, agent engineering, LLM red-teaming and GPU/inference engineering.
- **Legacy state mapping:** `done`+`doneAt` → `TASK_COMPLETED` on the original date; `timer.byDate` (minutes) →
  imported study sessions; weekly `notes` → weekly reflections; `weak:P` notes kept; `ms:`/`as:`/`pj:`/`st:`/`fn:` checks
  kept; a gate is marked passed only when all of its criteria were checked; `prefs.start`/`mustOnly` kept.
- **Behavioural changes by design:** gates and mastery never auto-complete; DSA revisions are never auto-completed;
  position follows completion rather than the calendar; the streak uses a unit threshold per local day.
- **Storage and sync model** (follows github.com/swaraj-acharya/PrepBoard): owner sign-in via `AUTH_ID`/`AUTH_PASSWORD`,
  progress in the browser plus your GitHub repo (`progress/events.json` + readable files), pushed only when you click
  "Push progress now", as one commit per push. No database.
- **Verification:** 39 automated tests; the push path was also exercised end to end through the real fetch-based GitHub
  adapter against a local mock of the GitHub REST API (lockout, login, sync password, one-commit push, no-op repeat,
  second push, cross-origin rejection, app files untouched). A push to the real github.com was not possible from the
  build sandbox — do one test push after deploying.
